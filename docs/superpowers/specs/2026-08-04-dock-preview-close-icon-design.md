# Dock 预览卡片关闭图标设计

日期：2026-08-04

状态：已确认，待实现

## 目标

调整 Dock 窗口预览中每张卡片的内容顺序，并为单张卡片提供明确、可验证的关闭入口：

- 将“应用图标 + 窗口标题”从缩略图下方移至缩略图上方。
- 在标题栏最右侧加入关闭图标；图标仅在该卡片悬停时显示。
- 左键点击关闭图标只请求关闭此卡片对应的真实窗口，不激活窗口。
- 只在确认真实窗口已销毁后移除对应卡片；其他预览卡片和面板保持显示。
- 最后一张卡片确认关闭后才隐藏预览面板。
- 未保存内容的确认、保存或取消全部由目标应用处理，本工具不显示第二个确认框。

## 范围与非目标

本次范围仅覆盖预览卡片上的新增关闭图标及其关闭后的局部状态更新。

不在范围内：

- 不改变右键菜单及其中“关闭窗口”的现有交互、动作路由或关闭后的面板策略。
- 不增加私有 API、AppleScript、模拟键盘输入或针对某个第三方应用的特殊逻辑。
- 不改变预览面板锚定、悬停延迟、缩略图捕获、窗口激活、桌面窗口放大预览或设置页。
- 不在本工具内处理文档保存、确认弹窗或批量关闭。

## 交互与视觉设计

### 卡片结构

卡片内容从当前的“缩略图、标题栏”重排为：

1. 标题栏：应用图标、单行窗口标题、关闭图标。
2. 缩略图：保持现有 fill / fit、加载中和不可用占位状态。

卡片宽度、高度、内边距、标题栏高度和缩略图尺寸保持不变。现有几何为 `232 x 172`，标题栏为 `28` 点，缩略图为 `220 x 124` 点；因此仅重排，不改变面板的横向/纵向布局或锚定结果。

标题只显示一行，按尾部截断。标题栏会永久预留关闭图标的固定槽位，避免长标题在悬停时发生宽度跳动或遮挡图标。

### 关闭图标状态

关闭控件使用系统 `xmark` 符号，固定在标题栏右侧，并使用固定点击区域：

- 默认：图标不可见、不可命中，也不出现在辅助功能树中。
- 悬停且可关闭：图标淡入，可通过鼠标左键点击；其提示和辅助功能名称使用已有本地化的“关闭窗口”文案并带上窗口标题。
- 悬停但不可关闭：保留同一位置的禁用图标，降低不透明度且不可点击。是否可关闭继续由既有 `WindowOperationAvailability` 的 `.closeWindow` 结果决定。
- 已发出关闭请求但尚未确认销毁：同一窗口的重复关闭请求被会话控制器忽略；不乐观移除卡片。

关闭控件与整张卡片的激活控件必须是两个同级按钮，不能把一个 SwiftUI `Button` 嵌套在另一个 `Button` 中。卡片主按钮覆盖卡片内容，关闭按钮在其标题栏位置覆盖为独立同级视图；关闭按钮获得命中时不会传递给主按钮。

## 架构与职责

### 预览视图与模型

`PreviewPanelView.swift` 负责呈现与意图转发：

- 重排 `PreviewCardView` 的标题栏和缩略图。
- 新增纯粹的关闭图标动作分发器。只有 `card.operationMenu.closeWindow.isEnabled` 为真时，才发送新的 `.closePreviewCard(windowID)` 面板动作。
- 保留 `.primarySelect(windowID)` 作为卡片其余区域的激活动作。
- 保留既有右键菜单桥接，继续发送 `.windowOperation(windowID, operation)`，不改动其语义。

`PreviewPanelModels.swift` 新增：

- `PreviewPanelAction.closePreviewCard(PreviewWindowID)`，使左键关闭图标与右键菜单操作在路由上明确区分。
- `PreviewPanelViewModel.removeCard(for:)`，只移除指定卡片并返回是否发生变更；不重建剩余卡片，从而保留已有缩略图和排序。
- 关闭图标的固定尺寸、间距和可用标题宽度指标，并更新标题宽度的纯几何测试。

### 真实窗口销毁观察

现有 `WindowPeekLifecycleObserver.swift` 已通过公开的 `AXObserver` 和 `kAXUIElementDestroyedNotification` 观察桌面窗口放大预览的当前目标窗口。该能力目前是单目标替换式订阅，不能直接承担多张卡片可能同时等待关闭的场景。

实现时将泛化这套现有能力为可取消的多窗口销毁订阅：

- 提供面向窗口 ID 和 `AXUIElement` 的订阅接口，返回取消令牌。
- 每个订阅独立维护公开辅助功能观察器、主运行循环 source 和匹配的目标元素。
- 保留生命周期观察器当前的单一桌面放大预览订阅，只将其改为使用同一订阅接口和令牌。
- `PreviewSessionController` 通过窄协议取得自己的关闭订阅；`AppDelegate` 保留既有生命周期观察器，并在收到应用终止事件时同时转交给会话控制器清理该进程的待关闭订阅。
- 订阅建立失败时记录结构化日志，但不阻止已有关闭服务发出关闭请求。

这样桌面窗口放大预览和待关闭卡片共享同一类公开 API 机制，却各自拥有独立订阅和清理生命周期。

### 预览会话控制

`PreviewSessionController` 负责关闭请求、销毁确认和面板增量更新：

1. 收到 `.closePreviewCard(windowID)` 后，先校验当前会话代次、窗口存在性、关闭能力和该 ID 是否已处于待关闭状态。
2. 在调用关闭服务前为该窗口登记销毁订阅，避免快速关闭时遗漏通知。
3. 复用 `WindowOperationService.perform(.closeWindow, on:)` 请求真实窗口关闭。它继续使用公开的辅助功能关闭按钮，目标应用自行处理未保存内容提示。
4. 请求失败时立即取消订阅、清除待关闭状态、保留卡片并记录现有失败详情。
5. 请求成功时不隐藏面板，也不移除卡片；等待目标 `AXUIElement` 的销毁通知。
6. 收到匹配且仍属于当前 generation / session epoch 的销毁通知时：取消订阅、清除待关闭状态、从 `currentWindowsByID` 和 `currentModel` 中移除该窗口，并通知 `WindowPeekCoordinator` 该目标已销毁。
7. 若仍有卡片，调用 `panelDisplay.update(model:)` 原地刷新面板；若已无卡片，调用现有隐藏路径并使用明确原因，例如 `closePreviewCard.lastCardClosed`。

在 `hide`、新会话替换、权限缺失和无窗口时，统一取消所有待关闭订阅并清空待关闭状态；应用终止时取消该进程的待关闭订阅。任何迟到通知都必须通过既有 generation / session epoch 保护被丢弃，不能移除新会话中的同 ID 窗口。

### 观察不可用的降级

关闭能力与销毁观察能力是不同的系统能力。若窗口支持关闭、但销毁观察无法建立：

- 仍执行用户明确请求的关闭操作。
- 不根据“关闭按钮按下成功”乐观移除卡片。
- 保留卡片直到下次 Dock 悬停带来的窗口重新查询；记录观察不可用的诊断日志。

这是安全优先的降级：在用户取消目标应用的未保存内容提示时，预览状态不会错误地宣称窗口已关闭。

## 状态与异常处理

| 情况 | 预览面板行为 | 真实窗口行为 |
| --- | --- | --- |
| 可关闭窗口，用户点击图标 | 保留卡片，等待销毁通知 | 请求目标应用关闭 |
| 用户取消未保存内容提示 | 卡片保持 | 窗口保持 |
| 用户确认关闭，收到销毁通知 | 只移除该卡片；最后一张时隐藏 | 窗口关闭 |
| 关闭按钮缺失或不可用 | 禁用图标，卡片保持 | 不发起请求 |
| 关闭请求失败 | 卡片保持并记录失败 | 窗口保持 |
| 销毁观察不可用 | 不乐观移除；下次悬停刷新 | 仍发起请求 |
| 会话已替换或面板已隐藏 | 丢弃迟到通知 | 不影响新会话 |

## 测试与验收

### 自动测试

新增或扩展测试覆盖：

- 标题栏在缩略图上方，固定关闭槽位纳入标题宽度计算，卡片和面板几何保持不变。
- 关闭图标仅在悬停状态显示；关闭能力不可用时不分发动作。
- 图标分发 `.closePreviewCard`，不会分发 `.primarySelect`。
- 已有右键菜单继续分发 `.windowOperation`，其现有行为不回归。
- 会话收到关闭图标动作时，先订阅、后调用现有关闭服务；重复请求不会重复调用服务。
- 关闭请求成功但尚未销毁时，面板不隐藏、卡片不移除。
- 销毁回调只移除匹配窗口，保留剩余卡片及其缩略图，并调用一次面板更新。
- 关闭最后一张卡片时隐藏面板。
- 关闭失败、观察不可用、用户取消导致没有销毁回调时，卡片保持。
- 旧 session / generation 的销毁回调不会影响新会话。
- 目标应用终止时，只释放该进程的待关闭订阅，不影响同一面板中其他卡片的订阅。
- 多窗口销毁订阅可独立取消；桌面窗口放大预览的既有单目标观察与生命周期测试继续通过。

### 手动验收

在具有系统辅助功能和屏幕录制权限的真实应用中验证：

1. 悬停多窗口应用，确认图标和标题位于每张缩略图上方。
2. 未悬停卡片时没有可点击关闭图标；悬停后图标出现，长标题仍单行截断。
3. 左键点击关闭图标，确认不会激活对应窗口，也不会关闭其他卡片。
4. 对未保存文档点击关闭，选择取消，确认该卡片仍在面板中。
5. 再次点击关闭并确认目标应用的保存/关闭提示，确认只移除该卡片，其余卡片持续可用。
6. 关闭最后一张卡片，确认面板隐藏。
7. 对无关闭按钮的窗口，确认图标禁用且不会触发关闭。
8. 右键打开现有窗口操作菜单并选择其关闭项，确认其行为与本改动前一致。

## 验收标准

- 左键关闭图标能够关闭其对应的真实窗口，且不会误触发窗口激活。
- 面板只在真实窗口确认销毁后移除匹配卡片；取消关闭不会移除卡片。
- 其他卡片在单张窗口关闭后继续显示、可悬停并可激活。
- 最后一张卡片关闭后，面板可靠隐藏且不会留下旧窗口放大预览。
- 所有实现使用公开 macOS API，自动测试、构建和现有窗口操作回归测试通过。
